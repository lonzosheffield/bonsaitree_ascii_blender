CF-1 — THE TIMELINE FILL NOW LANDS ON 100%
==========================================
docs/BRIEF.md, "Carry-forward defects":

  CF-1 — timeline fill can skip the final frame. In index.html's render(), the
  guard `Math.abs(pct - lastPct) > 0.01` suppresses the last update, leaving
  the progress fill stuck at ~99.992% while the page is held at bloom. Force
  the update when `frame.done` is true.

WHY IT BITES ONLY ON THE REAL RUN
---------------------------------
The guard is a paint throttle. One animation frame of a 3600 s run advances t
by 16.7ms / 3600s = 0.00046 percentage points, so the guard swallows about 22
frames out of every 23 — including the last one. On a compressed QA run
(?duration=6) each frame is worth 0.28 points, the guard never fires twice in
a row, and the bug is invisible. That is exactly why it survived M0.

THE FIX (index.html, render())
------------------------------
  if (frame.done || Math.abs(pct - lastPct) > 0.01) { ... }

`frame.done` is the clock's own t === 1 flag, so the final write always goes
through. The same `frame.done ||` was added to the MM:SS write, which has the
identical shape of guard.
