WHAT CHANGED (and what deliberately did not)
-----------------------------------------------------------------------------
UNCHANGED, on purpose:
  - GrowthClock still tracks wall-clock time and is never paused on hide.
  - src/shared/*, src/ascii/*, tools/, blender/, public/* are untouched.
  - The ASCII renderer needed no change: renderStep() paints the tree AS IT
    STANDS at a step index, so "catching up" is one buffer replay and exactly
    one repaint. It only needed to be TOLD the new t promptly, which is what
    the shell's visibilitychange -> clock.tick() now does, synchronously,
    before the first restored animation frame.

index.html
  - visibilitychange/pageshow -> clock.tick(): one synchronous emit lands the
    true t on every subscriber a frame earlier than the clock's own loop could.
  - Header counters are now both 1-based ("which of the N you are on", index+1
    capped at N). They read "STEP 001 / 512" beside "FRAME 001 / 600" at t=0
    (verified by screenshot) and "STEP 512 / 512" beside "FRAME 600 / 600" at
    t=1. The M3 gate's mixed-base wart ("STEP 000 / 512" next to
    "FRAME 001 / 600") is gone.

src/blender/panel.js
  - resume detection: a gap > policy.resumeGapMs (700 ms) between two presents
    means the PAGE was suspended, not that the network stalled. Belt and braces
    with an explicit visibilitychange/pageshow listener, so recovery also works
    where visibilitychange never fires (occlusion, minimise, screenshot pumps).
  - panel.resync(t): recompute t from the clock, re-seat the prefetch window,
    hold the last good frame.
  - priority: while recovering and the wanted frame is missing, the panel asks
    for that ONE frame and primes that ONE decode. Refilling the window first
    would put five other requests ahead of it on a six-connection budget and
    pay for them with the hold the viewer actually sees.
  - stall suppression: data-state="resyncing", never "stalled", for a resume.
    The stall timer is restarted on resume so the suspended minutes cannot be
    mistaken for a fault.
  - jump dissolve: a cold promote across >= 3 frames is faded in over 240 ms
    instead of cut in. The base holds at opacity 1 underneath for the whole
    transition, so the N5 "no background leak" rule still holds.
  - FrameCache now frees a connection slot the instant an in-flight fetch is
    aborted by the window re-seat (it used to wait for the abort to settle, so
    the one urgent frame could be refused a slot). This also closes a latent
    double-decrement of inFlight.
